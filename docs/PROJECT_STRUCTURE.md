# Структура проекта

## Почему страницы сайта пока лежат в корне

Study Guide сейчас публикуется как статический сайт. HTML-страницы и связанные с ними CSS/JS-файлы используют относительные пути от корня домена (например, `styles.css`, `app.js`, `data.js`). Поэтому перенос этих файлов в произвольные папки без полноценной перенастройки путей сломал бы загрузку страниц и GitHub Pages / текущий хостинг.

Корень намеренно оставлен как публичная web-root зона.

## Карта корня

### Страницы
- `index.html` — главная и каталог.
- `vuzi.html` — раздел вузов/колледжей.
- `exams.html` — подготовка к экзаменам.
- `courses.html` — каталог учебных курсов.
- `account.html` — регистрация и личный кабинет.
- `admin-courses.html` — редактор курсов (доступ ограничивается серверной проверкой).

### Клиентский код
- `styles.css` — общие стили.
- `app.js`, `main.js`, `content.js`, `icons.js` — логика интерфейса и контент.
- `data.js`, `data-extra.js` — данные каталога.
- `courses.js`, `account.js`, `admin-courses.js` — соответствующие разделы.
- `supabase-config.js` — только публичный URL и publishable key. Секреты здесь запрещены.

### Папки
- `assets/` — изображения и статические ресурсы.
- `supabase/functions/` — исходники серверных Edge Functions.
- `docs/` — документация проекта и инструкции по эксплуатации.

## Правила дальнейшей уборки

1. Не перемещать HTML/CSS/JS из корня, пока не будет отдельной задачи на миграцию путей и проверку всех страниц.
2. Новую документацию помещать в `docs/`.
3. Изображения, шрифты и прочую статику помещать в `assets/` с подпапками по типу ресурса.
4. Не хранить в Git `.env`, ключи, пароли, логи, локальные зависимости и собранные артефакты.
5. Удалять файл только после проверки, что на него нет ссылок и он не используется сборкой/хостингом.
